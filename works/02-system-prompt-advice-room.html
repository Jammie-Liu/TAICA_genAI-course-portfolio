System Prompt｜煩惱諮詢室

三位成員輪流回覆煩惱投稿：先事實暴擊、再互相吐槽，最後給真心建議。

作品概述

一個煩惱諮詢對話機器人。使用者投稿戀愛、人際、課業或人生方向的煩惱，機器人會用三位成員 Blo、Tuka、Mithra 輪流發言的對話劇本回覆。System prompt 寫了「短版」與「詳細版」兩種。

動機

靈感來自 Epik High 的 YouTube 頻道 EPIKASE 的戀愛諮詢系列：三位成員先直白點出問題，再互相吐槽製造笑點，最後回到正經、給出真誠溫暖的建議。我想把這種「好笑但真的有幫助」的諮詢氛圍，做成一個 AI 對話機器人。

使用技術

技術 在這個作品的用途
System Prompt（短版） 只交代角色、形式與核心規則，看模型在少量指示下能否掌握風格
System Prompt（詳細版） 加入四段式結構、格式與語氣規則、禁止事項，讓角色表現穩定
角色設定 三位角色分工：Blo 點出問題、Tuka 製造笑點、Mithra 溫暖收尾
Few-shot 範例 詳細版附兩則完整範例，示範對話節奏與語氣
提示安全規則 遇到自我傷害或暴力時停止搞笑，提供求助資源

運作方式

  1. 第一反應：三人對投稿做出驚訝、心疼或憤怒的反應。
  2. 事實暴擊：Blo 直接點出問題核心，Tuka 補刀或提出一個荒謬解法。
  3. 吐槽插曲：三人互相吐槽一兩句，例如怕老婆看到而趕快補救。
  4. 真心建議：回到正經，給 2–3 個具體可行的建議，最後由 Mithra 收尾。

設計重點

  • 搞笑不超過一半：寫成明確規則，確保使用者每次都能帶走真正有用的建議。
  • 不一味站在投稿者那邊：投稿者自己有問題時，要溫柔但誠實地指出；也不替使用者做重大人生決定。
  • 禁止空泛雞湯：不說「做自己就好」「時間會沖淡一切」這類沒有內容的話。
  • 致敬，不扮演本人：角色是為了重現節目氣氛而設計的原創人物，規則中禁止捏造真實成員的私生活或經歷。
  • 安全規則最優先：提到想傷害自己或遭受暴力時，三人停止吐槽，改用溫和語氣，並提供安心專線 1925、生命線 1995、張老師 1980、保護專線 113。

範例

詳細版 system prompt 中的 few-shot 範例之一：

投稿：男朋友叫錯我的名字，叫成他前女友的名字，我該原諒他嗎？

Blo（坐起來）等一下，前女友的名字？這個是要判刑的吧。

Tuka我有解法，你明天開始也改名，改成他前女友的名字，以後就不會叫錯了。

Mithra……這不是解法吧。

Blo好啦好啦，認真講。叫錯一次可能只是習慣，重點是他叫錯之後的反應。

Mithra如果他馬上道歉、也願意聊，那是可以慢慢修復的。

Blo但如果他裝沒事，或還在跟前女友聯絡，那問題就不是名字了。

Tuka（突然正經）你會投稿，代表你很在意。在意就跟他說，不要自己吞下去。

Mithra你值得被叫對名字，也值得被好好放在心上。

延伸方向

  • 用同一組投稿比較短版與詳細版的輸出，觀察 system prompt 的詳細程度對角色一致性的影響。
  • 回覆要同時顧到很多規則，一次生成容易漏掉其中幾項；後來改用 Planning 的方式重做，見作品 04。
